# Mobile publication M3 lessons

Source preparation, independent review, exact package admission/publication and
signature/asset verification are complete.

Coordinate the twelve family examples with their manifests. Mixed 0.2.1 and
0.3.0 examples can create distinct security_core types even when each crate
compiles independently. Package README links must resolve outside the archive
through an immutable release-tag URL when guidance is kept at repository level.

Read actual public API declarations before claiming a compatibility break.
DataError is non-exhaustive; the new MobileKeyProvider { kind } variant extends
its typed outcomes. The new mobile capability still warrants a minor release.

Reuse native qualification evidence only while implementation bytes remain
unchanged. Publishing software references does not qualify physical custody,
consumer FFI ownership or application reconciliation. Each exact Cargo package
requires its own source/graph/provenance and OSV admission before verification
builds, even when the root dependency graph is unchanged.

No new issue or consumer scope is introduced: physical and Guardian integration
remain the existing downstream issue98/Guardian acceptance boundary.

The registry approval record must precede the release tag. Use the immutable
package source commit separately from the later checksum-metadata commit. For
0.3.0 all twelve exact archives/registry bytes, 27 signatures, twelve SBOM schemas
and 54 uploaded assets were independently verified. Metadata-only admin merge
can avoid redundant rebuild latency after unchanged source has full platform
checks, root OSV and read-only producer verification; it never admits new code or
dependencies. No new follow-up issue: consumer physical/binding/reconciliation
limits remain in existing Guardian issue1503.
